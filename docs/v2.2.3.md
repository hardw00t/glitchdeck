# v2.2.3 release notes

- `exec_run` runs an argv array through a tape when the server starts with `--allow-exec`. This grants arbitrary command execution as the server user, not a sandbox; the child can access files and open sockets directly. Proxy egress is limited by the server's `--upstream-allow`, which a call cannot widen.
- MCP tape exports default to v2; `format: "v1"` preserves compatible v1 exports and rejects v2-only recordings. Incomplete exports report `replayable: false`.
- Invalid-params errors include sanitized `data.field` and `data.reason`; fault parameter errors include known range and enum hints.

## Execution isolation and limits

The execution path addresses five hazards: inherited MCP stdout descriptors could let a child forge protocol frames; inherited stdin could let it consume requests; output teeing could corrupt the protocol stream; the reverse-proxy target exemption could bypass the egress allowlist; and the old 4 KiB output tail repeatedly copied on overflow. Execution detaches stdio, enforces server egress policy, and captures bounded output with byte counts.

The default timeout is 30 seconds, with a maximum of 300 seconds. The worst-case wall time including the two-second grace period, process wait delay, and drain is under 320 seconds. Unix cleanup uses process groups; Windows cleanup is best-effort and does not guarantee stopping grandchildren. Workdir-relative `cwd` is checked after resolving symlinks, but a symlink writable by the child can be swapped between validation and process start (TOCTOU); this is not a sandbox.

On Linux the detached helper must acknowledge startup within the job deadline before it can start the command. It receives argv separately rather than packing it into one environment variable; native process-launch limits still apply. Standalone Unix MCP marks launcher-inherited descriptors above stderr close-on-exec, and the detached child receives EOF on stdin, a `PWD` matching `cwd`, and only the private listener in `NO_PROXY`.

Detached HTTP assertions use the server's dial policy, pin `localhost` to loopback, reject oversized JSON bodies, and report mismatched fields without values. The final proxy wait gets a fresh grace window bounded by the job deadline. Detached warnings are collected in the report; MCP stderr diagnostics are best-effort so a blocked reader cannot prevent cleanup. These changes do not alter legacy CLI execution.

## Batches and cancellation

Only one `exec_run` or non-batch `tape_run` job runs at a time; a second long call returns `BUSY`. Other methods, including `ping`, remain responsive. `exec_run` is not batchable; `tape_run` in a batch runs inline and is not cancellable. Send `notifications/cancelled` with the request ID to cancel a non-batch job; no response is sent for the cancelled request. Responses to other requests can arrive out of order and are matched by ID.

`BUSY` diagnostics bound the displayed request ID without changing cancellation matching. The next sequential call waits for the prior response's write to finish without admitting a second running job. Clean stdin EOF still waits for the running job; a scanner or transport error cancels it immediately.

File exports retain `out_path` and add a workdir-relative `tape_path` usable by `exec_run`. The SSE decode regression also checks that the decoder has not read the whole compressed source at the line limit.

## Local stdio smoke results

- `EXEC_DISABLED` without opt-in.
- SSE cut: `ok=false`, `child_exit=1`, stdout `missing finish_reason after a clean SSE EOF`.
- Cancel: `ping` id 8 answered, no reply for id 7, process group gone.
- Child fd listing: `0, 1, 2, 3` (the listing opens fd 3); no MCP stdout pipe.
- Remote target without server allowlist: `EGRESS_POLICY`.
- With the target allowlisted and TLS enabled, the anonymous request returned HTTP `401` (`intercepted_ok=1`, `egress_denied=0`).
- Export: v2 validated and v1 bytes matched v2.2.2.
- Invalid params: `type_mismatch`, `unknown_field`, and `too_long`.
- SSE decode limits: `-race -count=200` passed in 434.358 s. The 50-repeat run also passed alongside three full race-suite runs at `GOMAXPROCS=2`. Raising the decoder limit in a temporary overlay made the unit test fail for all three encodings.
