# v2.2.1 release notes

- Pass pinned CONNECT hosts through without interception while keeping the upstream allowlist and resolved-IP restrictions in force.
- Merge inherited proxy bypasses and CA files into the child environment. Drop inherited bypasses that cover the target; explicit `--no-proxy` entries still win.
- Fail `exec` on TLS-rejected-only or egress-denied-only traffic, and report traffic counters and runtime hints.

## Local smoke tests

| Scenario | Observed result |
| --- | --- |
| curl with the merged private CA | Exit `0`; upstream `Issuer:CN = Demo Private Root`; `passthrough_ok=1`, `tls_rejected=0`. The proxy wire event had `tunnel: passthrough, passthrough: localhost`. |
| Python Requests and Node fetch with inherited `SSL_CERT_FILE` | Both exited `0` with HTTP `200` and `passthrough_ok=1`. Node also passed with the private root supplied through `NODE_EXTRA_CA_CERTS`. |
| Git through intercepted HTTPS | `git ls-remote` returned `refs/heads/main`; `intercepted_ok=1`. Deno was not installed. |
| Passthrough without corresponding egress permission | Exit `1`; `egress_denied_only` named `evil.test`, with no dial failure. |
| Passthrough on a `0.0.0.0` listener | CONNECT to `localhost`, `127.0.0.1`, and `169.254.169.254` each returned `502` before connecting upstream. |
| Inherited `NO_PROXY` covered the loopback target | `no_proxy: dropped "localhost" from inherited NO_PROXY`; both child variables matched, and the forwarded curl request triggered a fault. |
| Client TLS rejection | curl with `/dev/null` and Python Requests with unrelated roots each exited `1` with `tls_rejected=1`. Requests reported `tls_rejected_only`; `--allow-zero-traffic` allowed a wrapper that handled the failure to exit `0`. |
| Mixed traffic | Exit `0`; `warning: tls_rejected: 1 handshake(s) failed for hosts localhost`; `intercepted_ok=1`, `tls_rejected=1`. |
| Absolute-form request without an egress allowlist match | Exit `1`; `egress_denied_only` named `example.com`. |
| Go loopback bypass and reverse mode | Direct localhost access reported `zero_traffic` and the reverse-mode hint. Using `GLITCHDECK_PROXY_URL` triggered the fault and exited `0`. |

For Node on Linux, a runtime that supports `NODE_USE_SYSTEM_CA` can load the inherited `SSL_CERT_FILE` through the merged bundle. On older runtimes, macOS, or Windows, put private Node roots in `NODE_EXTRA_CA_CERTS`.

`tls_rejected` measures handshake failures observed by the proxy. On curl 8.18.0 with OpenSSL, a valid but unrelated `--cacert` file produced curl exit `60` after the proxy recorded `intercepted_ok=1`; the default child-exit assertion still failed, but the proxy could not attribute the later rejection to the handshake.

All 37 example tapes validated. The 36 existing replays matched v2.2.0 exit codes, stderr, and JSON results apart from elapsed `duration_ms`.
