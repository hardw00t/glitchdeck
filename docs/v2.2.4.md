# v2.2.4 — First-Run Friction Patch

- `exec` now counts failed reverse-target dials in `exec.traffic.dial_failed` and exits nonzero with the target host and port, even if the child accepts the proxy's error response.
- `exec.traffic.egress_denied_hosts` and stderr name up to 10 distinct denied hosts in sorted order, even when other requests succeed. Remote tape targets rejected by `exec` now suggest forward mode with `--tls` and an upstream allowlist. Egress policy and TLS verification are unchanged.
- `rate-limit` derives `Retry-After` by rounding `retry_after_ms` up to whole seconds (minimum 1). An explicit `retry_after_sec` wins; without either setting, the default remains 5 seconds. The Anthropic preset still emits `Retry-After-Ms` when set; this header has not been verified against the live Anthropic API.
- Starter tapes document the existing `--target` port override. The README and SKILL explain how to adapt route matchers, and the README shows how to pin `--listen` for a config-file base URL. The Stripe timeout/retry starter accepts senders that exit nonzero on the injected `504` and still requires the fault to fire.
- Target reports omit URL paths and invalid targets and normalize ports. Denial events and host lists share the same bounded hostname filter. Dial accounting includes refused reverse replays, excludes cancellations and discarded reset generations, and records dial-time policy blocks as egress denials without changing the response.
- Dial accounting counts request-visible failures, not background attempts abandoned by the transport. Traffic snapshots retain completed counters and their denied hosts on drain timeout. Public denial events omit request paths, headers and body previews; protocol assertions still match using private admission metadata.
- Assertion evidence retains tape-owned match keys and resets with traffic. Denied webhook replay events keep the replay mode and the original delivery result without exposing request URLs, headers, or bodies.
