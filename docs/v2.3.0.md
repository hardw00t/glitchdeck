# v2.3.0 — Hybrid Cassettes

A v3 tape can store the live upstream response separately from the client script and fault rules. Existing v1 and v2 tapes still use the live upstream by default.

| Mode | Commands | Upstream |
| --- | --- | --- |
| `passthrough` (default) | `exec`, `test` | Live, with the existing egress and TLS policy |
| `record` | `exec --mode record --tape-out recorded.yaml` | Live; save the response before faults alter it |
| `replay` | `exec --mode replay`, `test --mode replay` | In-process cassettes; no upstream dial, DNS, redirect follow, or passthrough tunnel |

## Capture and matching

Record mode requires an explicit output path and changes the input only if it is also the output. Recording retains the status, permitted response headers and up to 4 MiB of body. Gzip SSE is stored decoded without `Content-Encoding`; recorded responses also exclude `Set-Cookie` and the request credential-header deny-list. Encoded partial responses are incomplete rather than replayed with stale byte offsets. Synthetic responses and resets before headers have no upstream body to record. Truncation, in-flight bodies, and buffer eviction can make the recording incomplete and unusable for replay.

Legacy versions 1 and 2 have a 64 MiB serialized input limit. Version 3 also has a 16 MiB serialized limit and a 256-cassette limit, with at most 8 MiB of decoded response bodies combined and 4 MiB per body. Plain v3 version declarations are checked before parsing oversized input; other YAML forms use the 64 MiB raw ceiling before version validation. The recorder shares its 8 MiB byte budget across retained traffic and in-flight captures. At most 32 response captures can run at once per recording; reaching that limit marks the recording incomplete without interrupting live proxy traffic.

`cassettes` and `ignore_json_paths` require `version: 3`. Cassette keys use the case-insensitive HTTP method, exact path without query, and host when present. Ties compare SHA-256 digests of canonical JSON after removing the tape's dotted `ignore_json_paths`. Non-JSON request bodies are hashed as raw bytes. Response bodies are UTF-8 or use `body_encoding: base64` when binary.

Replay applies fault rules to the selected response. A miss returns HTTP 502 and reports `cassette_miss`; unresolved ties report `cassette_ambiguous`. Matching stops with `cassette_match_limit` if JSON exceeds the structural bound or concurrent matching exhausts its shared budget. These failures cannot be overridden with `--allow-zero-traffic`. A v3 tape with no cassettes cannot run in replay mode. CONNECT can only be intercepted locally; redirects can stay on the replay listener but are not followed upstream. Child endpoint variables point to local replay listeners, not live services. The proxy does not sandbox arbitrary child sockets.

```sh
glitchdeck validate examples/tapes/your-app-openai-sse-cassette.tape.yaml
glitchdeck test --mode replay examples/tapes/your-app-openai-sse-cassette.tape.yaml
```

## Export secret gate

Console export, record tape output, and all MCP tape export formats scan URLs, remaining headers, and request and response bodies, including decoded gzip and encoded cassette bodies. The closed, case-sensitive pattern set (except the Bearer prefix) covers:

- OpenAI `sk-` followed by at least 20 token characters; Anthropic `sk-ant-`.
- Stripe `sk_live_`, `sk_test_`, `rk_live_`, `rk_test_`, and `whsec_`.
- AWS `AKIA` followed by 16 uppercase alphanumeric characters.
- PEM private key blocks.
- GitHub `ghp_` and `github_pat_`.
- `Bearer eyJ` JWT-like values.

Export fails closed with `unsupported_encoding` or `uninspectable` when a representation cannot be inspected safely. This includes invalid or unsupported compression, transfer encodings, charsets and archive containers; malformed MIME, `message/*`, and `multipart/digest`; MIME encoded words and encoded or continued header parameters; unfinished escape-bearing JSON strings; and private-key spans that cannot be removed in full. Declared and signature-detected gzip and zlib use bounded decoding. Every retained HTTP and MIME header value is scanned both as text and with URL/query semantics. Inspection has depth and work limits; exceeding either blocks export.
Blocked exports report the secret family and a scanner-defined field path, not the credential, header name, or local file path. CLI exits `2`; MCP returns `EXPORT_BLOCKED`. `--redact-secrets`, the console redaction option, or MCP `redact_secrets: true` replaces safely rewritable material with `REDACTED` and sets `redacted: true`. Output is emitted only after a clean rescan. There is no bypass. Review recordings before sharing; patterns cannot find arbitrary credentials.
Wire logs and telemetry are not secret-scanned; do not share them.

Console and MCP exports use v3 when cassettes are present and v2 for request-only recordings. MCP `format: "v1"` or `"v2"` removes cassettes only after scanning and only affects inline output for cassette recordings. `out_path` remains available for request-only v1/v2 exports inside the MCP workdir. Record mode streams the child's own output to the terminal as passthrough does. Child output is not scanned or redacted; JSON reports and `--report` omit it, the child arguments, and local paths. Glitchdeck's own record diagnostics never log wire data, and a failed report write does not replace an `EXPORT_BLOCKED` verdict.

## Known limitations

- The recorder allows 32 concurrent response captures, an 8 MiB capture budget, and 4 MiB per body. These are not process-memory limits: temporary decoder buffers for compressed MIME parts, headers held while responses stream, and duplicate-webhook replay buffers are not all charged to those budgets.
- Redirects and demo TLS replay are best-effort. A followed redirect can change when a fault activates or which hop gets credit for it; replay can also misidentify a hop when the query was redacted or the request body changed. Host-scoped demo TLS rules and tapes recorded through the TLS console can depend on the original authority.
- Same-origin browser writes can be rejected when sent through an explicit proxy to the replay target listener; connect directly to that listener.
- In request-only recordings, a provisional cassette path can retain additional bytes that are not charged to the recording budget.
- The export scanner checks retained representations, but does not detect credentials split across separate SSE events and reassembled only by a client.
- Bodies with encodings glitchdeck cannot decode for scanning (for example gRPC message compression) and XML documents that declare entities or an internal DTD subset are blocked from export (or replaced by a redaction marker with --redact-secrets) by design.
- Text bodies outside UTF-8, US-ASCII and UTF-16 (with BOM) are blocked from export (or replaced by a redaction marker with --redact-secrets) by design.
