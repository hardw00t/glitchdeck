# v2.3.0 — Hybrid Cassettes

A v3 tape can store the live upstream response separately from the client script and fault rules. Existing v1 and v2 tapes still use the live upstream by default.

| Mode | Commands | Upstream |
| --- | --- | --- |
| `passthrough` (default) | `exec`, `test` | Live, with the existing egress and TLS policy |
| `record` | `exec --mode record --tape-out recorded.yaml` | Live; save the response before faults alter it |
| `replay` | `exec --mode replay`, `test --mode replay` | In-process cassettes; no upstream dial, DNS, redirect follow, or passthrough tunnel |

## Capture and matching

Record mode requires an explicit output path and changes the input only if it is also the output. Recording retains the status, permitted response headers and up to 4 MiB of body. Gzip SSE is stored decoded without `Content-Encoding`; recorded responses also exclude `Set-Cookie` and the request credential-header deny-list. Synthetic responses and resets before headers have no upstream body to record. Truncation, in-flight bodies, and buffer eviction can make the recording incomplete and unusable for replay.

Version 3 loading is limited to 16 MiB of serialized input and 256 cassettes, with at most 8 MiB of decoded response bodies combined and 4 MiB per body. Version 1 and 2 tapes keep their previous loading behavior. The recorder shares its 8 MiB byte budget across retained traffic and in-flight request and response captures.

`cassettes` and `ignore_json_paths` require `version: 3`. Cassette keys use the case-insensitive HTTP method, exact path without query, and host when present. Ties compare SHA-256 digests of canonical JSON after removing the tape's dotted `ignore_json_paths`. Non-JSON request bodies are hashed as raw bytes. Response bodies are UTF-8 or use `body_encoding: base64` when binary.

Replay applies fault rules to the selected response. A miss returns HTTP 502 and reports `cassette_miss`; unresolved ties report `cassette_ambiguous`. The run fails on either, including with `--allow-zero-traffic`. A v3 tape with no cassettes cannot run in replay mode. CONNECT can only be intercepted locally; redirects can stay on the replay listener but are not followed upstream. Child endpoint variables point to local replay listeners, not live services. The proxy does not sandbox arbitrary child sockets.

```sh
glitchdeck validate examples/tapes/your-app-openai-sse-cassette.tape.yaml
glitchdeck test --mode replay examples/tapes/your-app-openai-sse-cassette.tape.yaml
```

## Export secret gate

Console export, record tape output, and all MCP tape export formats scan URLs, remaining headers, and request and response bodies, including decoded gzip and encoded cassette bodies. The closed, case-sensitive pattern set (except the Bearer prefix) covers:

- OpenAI `sk-` followed by at least 20 token characters; Anthropic `sk-ant-`.
- Stripe `sk_live_`, `sk_test_`, `rk_live_`, `rk_test_`, and `whsec_`.
- AWS `AKIA` followed by 16 uppercase alphanumeric characters.
- PEM private key blocks.
- GitHub `ghp_` and `github_pat_`.
- `Bearer eyJ` JWT-like values.


HTTP bodies with invalid or unsupported content encoding are not exported as opaque bytes. An encoded body that cannot be inspected safely blocks export.
Blocked exports report the secret family and field path, not the credential or a local file path. CLI exits `2`; MCP returns `EXPORT_BLOCKED`. `--redact-secrets`, the console redaction option, or MCP `redact_secrets: true` replaces detected material with `REDACTED` and sets `redacted: true`. Output is emitted only after a clean rescan. There is no bypass. Review recordings before sharing; patterns cannot find arbitrary credentials.
Wire logs and telemetry are not secret-scanned; do not share them.

Console and MCP exports use v3 when cassettes are present and v2 for request-only recordings. MCP `format: "v1"` or `"v2"` removes cassettes only after scanning and only affects inline output for cassette recordings. `out_path` remains available for request-only v1/v2 exports inside the MCP workdir. Record-mode CLI diagnostics omit child output, arguments, and paths; a failed report write does not replace an `EXPORT_BLOCKED` verdict.

## Local-mock smoke checks ($0)

It checks zero target accepts in replay, live accepts in passthrough, a blocked export with no output file, and a clean redacted export. No provider credentials or paid calls are used.
